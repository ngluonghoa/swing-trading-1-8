5. GĐ3/B3 — SỬA LỖI LOGIC THIẾT KẾ CANONICAL CANDLE


Actual edit: appended Section 16 “ENGINEERING REVISION v0.1” to 05_GD3_DATA_CONTRACT_SMART_CACHE_ARCH. The old CanonicalCandle.close_status mixed three orthogonal properties and could imply a finalized bar has complete trustworthy source minutes. New proposed v1.1 contract uses:
- lifecycle_state OPEN|CLOSED (clock/cutoff only)
- coverage_state COMPLETE|SESSION_PARTIAL|RANGE_PARTIAL|SPARSE_UNVERIFIED|UNKNOWN|INVALID (data coverage/calendar)
- quality_state VERIFIED|WARN|UNVERIFIED|BLOCKED (source/adjustment/provenance)
Example: CLOSE + SPARSE_UNVERIFIED + UNVERIFIED is valid and must not generate a confirmed B/S signal. Session-partial may be verified when calendar confirms expected session cutoff. OPEN + observed COMPLETE is still not confirmed until proper source/clock cutoff. Explicit schema migration from legacy enum required in code.
Cache L1–L5 cover all inputs outside candles too: index/sector/quotes/corporate actions/indicators/structure/zones/audit; track source & normalized digest, release/schema fingerprints, stale and revision, no corrupt cross-release reuse. Reused evidence must be revalidated by dependency snapshots and freshness. No persistent runtime cache implemented.
B3 acceptance checklist DC-01..DC-10 is a PLAN, not completed Python tests.


6. GĐ3/B4 — PHÁT HIỆN BUG TRONG THỬ NGHIỆM M15 ARMED


Actual edit: appended Section 14 “ENGINEERING REVISION v0.1” to 06_GD3_EARLY_DETECTION. Prior B4 JS synthetic 40/40 tests were accurate for the scenarios listed but did not test repeated 5-minute scans over the SAME closed M15 bar. Old state incremented farCount on every invocation with m15Closed=true, potentially disarming after re-reading the same bar twice. Must instead increment only once per unique CLOSED M15 bar ID (deduplicated by canonical key and revision); if bar corrected, replay from prior checkpoint rather than count new event.
Proposed state must carry bar_id, last_evaluated_closed_m15_bar_id, unique event ids, zone_id+revision, source/canonical bar revision, position/release/rule/param/calendar version; idempotency and attempt bounded Step03→Step05 flow. TTL/hold/cooldown must use a defined calendar-aware clock (active trading minutes or wall time, approved/versioned); lunch/overnight/holidays cannot silently expire a zone. Price-basis/source invalid: no confirmed M5; position protection warnings must still be surfaced with reliable fallback evidence.
New POC design regression: 6/6 synthetic JS cases PASS (same closed bar read twice only counts once; second unique bar increments; bad source doesn't increment; CLOSED+SPARSE can coexist; OPEN+COMPLETE can coexist; clean CLOSED+COMPLETE+VERIFIED distinct). This is NOT an executed Python suite and should not be mixed into the historical 40/40 result.
