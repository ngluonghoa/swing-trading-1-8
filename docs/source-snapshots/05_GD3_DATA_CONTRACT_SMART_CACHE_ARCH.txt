CalendarRegistry key = (exchange, trading_day, schedule_version). Mỗi sàn có session rules, special event policy, holidays, afternoon trading slots, auction/afterhours semantics; không suy theo giờ chung toàn thị trường. Bước 2 quan sát: HOSE/SSI liên tục 09:15–11:30, 13:00–14:30 và event14:45; HNX/SHS có M1 từ 09:00, event14:45; UPCOM/VGI từ 09:00 tới 14:59 với nhiều slot không có record; VNINDEX có thêm boundary rows 11:30 và 14:30. Đây là cấu hình DẪN XUẤT TỪ MẪU, chưa chính thức xác minh semantics của tất cả khớp lệnh, HNX PLO hay ATO/ATC.
Bucket [start,end): M5/M15/M30/H1 neo theo phiên/segment lịch sàn, không ghép xuyên 11:30–13:00; H1 segment ngắn 15/30 phút gắn coverage_state=SESSION_PARTIAL khi đã được lịch xác minh, không mặc nhiên trùng provider-native H1. W1 tổng hợp từ D1 theo calendar_version; tuần còn diễn ra biểu diễn lifecycle_state=OPEN, coverage_state=UNKNOWN hoặc trạng thái đầy đủ theo phạm vi ĐÃ QUAN SÁT được ghi rõ, quality_state theo bằng chứng nguồn, KHÔNG dùng legacy OPEN_PROVISIONAL. Khi W1 đóng đúng cutoff đã xác minh, mới chuyển lifecycle_state=CLOSED; tuần đầu thiếu đầu cửa sổ => coverage_state=RANGE_PARTIAL ngay cả khi calendar period đã CLOSED. Với nguồn open/incomplete không gắn VERIFIED cho confirmed trading. Auction cuối ngày/inclusion/special events phải versioned policy + evidence trước source acceptance; chưa có chính sách thì UNKNOWN/UNVERIFIED, không tự công nhận FULL coverage.
NoTradeMinutePolicy=UNVERIFIED đối với phút không xuất hiện trong raw/source record, KHÔNG có nghĩa mọi volume=0 đều sai. Chỉ khi provider/exchange xác minh true no-trade (theo nguồn order/trade/native candle và đúng session), bar có volume=0 có thể là dữ liệu HỢP LỆ với lifecycle/coverage/quality độc lập; numeric ratio phải xử lý mẫu số zero riêng, không coi 0 volume là missing. Không chèn phút volume=0/carry-forward để giả dữ liệu đầy đủ; observed_minutes, expected_minutes và gap_reason lưu riêng. Derived OHLC bar trống không được tự tạo nếu source policy thiếu chứng cứ.

6. DAG PHỤ THUỘC VÀ INVALIDATION CHỈ TÁC ĐỘNG


ROOT SOURCES: PROVIDER_M1, PROVIDER_D1, INDEX, SECTOR, CORPORATE_ACTIONS, CALENDAR, RULE_VERSION, PARAM_VERSION, INDICATOR_VERSION, STRUCTURE_VERSION, POSITION, UI_VERSION, AUDIT_POLICY, UNIVERSE.
Direct edges (conceptual, filtered by symbol/TF/date/feature): PROVIDER_M1/D1/CALENDAR/CORPORATE_ACTIONS -> L1; L1 plus INDEX/SECTOR -> L2; L2+L1 -> L3; L3+L2+RULE/PARAM/POSITION -> L4; L4+UI_VERSION+AUDIT_POLICY -> L5.
Important granular rule: Do NOT invalidate every stock because one symbol's M1 changed. Invalidate affected symbol/session/TF and downstream series that reference it, plus market/industry dependent objects. D1 revision at day t invalidates W1 week containing t, indicator rolling/smoothing tail from affected point through latest, pivots whose right-bars span t, zone windows, audits and reports for affected runs. Corporate action may rewrite a whole affected historical segment, so rerun adjustment lineage and all consumers.
Change provider index only: market/RS indicators for dependent symbols -> L2,L3,L4,L5; no need to rewrite unrelated raw stock L1. Change RULE/PARAM: L4,L5; L1–L3 reusable only if rule does not alter required indicator/structure definitions (otherwise include their config versions in L2/L3 and invalidate corresponding nodes too). Change UI_VERSION alone -> L5 renderer only, NO recalculation signal; but UI-1.0 cannot be changed without user approval. Position change -> Exit Protection/strategy L4, audit L5; independent price caches unchanged.
Invalidation state transitions: VALID -> DIRTY (on verified upstream change) -> REBUILDING -> VALID on snapshot match; ERROR on failed build; STALE if data age violates feature-specific freshness. Missing upstream data -> UNVERIFIED, not 'NOT_DETECTED'. Keep lineage for both old and new revisions; no in-place silent overwrite of evidentiary history. Affected window / tail recalculation is algorithm-specific: EMA/ATR/RMA often recalc from first changed bar to end; rolling SMA can use window-limited recompute, structural pivot right-window can be broader. Do not assume a fixed 20-bar invalidation span for every indicator.


7. CONTENT-ADDRESSED FINGERPRINT & SNAPSHOT CONTRACT


Canonical cache fingerprint = SHA-256(canonical serialization of {project, environment, symbol/exchange, normalized_data_digest, session_calendar_version, adjustment_revision, source_provider_id/entitlement/coverage, algorithm+indicator version, relevant parameter/rule versions, strategy, dependencies' fingerprints, last_closed_bar_time, quality flags affecting feature}). Canonical serialization stable field order, explicit null, units/timezone, Decimal-to-string, sorted dependency list; salt not needed for public nonsecret data; never include secrets/API keys.
Two distinct identifiers: (A) source content digest for byte-level payload compare + (B) normalized data digest after canonical parse/standardization, so changing only response metadata does not recompute all outputs; do not treat HTTP response time as price revision. Idempotent run ID and report commit ID keep history even when provider repeats same snapshots.
CacheEntry = {layer, artifact_type, symbol, timeframe, strategy|null, key, fingerprint, upstream_fingerprints:list, origin_run_id, observed_at, computed_at, valid_until_policy, state:VALID|DIRTY|REBUILDING|STALE|UNVERIFIED|ERROR, data_quality, size_bytes, provenance, last_closed_time, partial_state_fingerprint, computed|reused_validated, evidence_storage_id}.
Store immutable completed-bar state separately from latest open/provisional candle. Provisional output is transient overlay with own revision, never commit smoothing indicators as if bar had closed. On close, use one canonical finalization and invalidate minimal descendants. Cache VALID requires matching all dependency fingerprints and actual completeness constraints, not just time TTL.


8. THUẬT TOÁN 5-PHÚT: INCREMENTAL UPDATE / REUSE


Requested scan (user-triggered, no automatic background job presumed):
(1) Parse request(s) symbol/strategy; new run_id, decision_at, market calendar. Resolve source capability and market open/closed. Fetch provider only for changed time windows if API supports true delta; SSI MCP hiện có lúc phải lấy full day 1m rồi so digest/delta tại client. Ghi API calls, bytes, latency, provider mode, thực tế chứ không báo 'chỉ tải 5 phút' khi full-day fetch.
(2) L1 load previous confirmed snapshot, compare new records using stable id (symbol,TF,time,source,payload digest); classify APPEND|REVISE|DELETE|NO_CHANGE|SOURCE_ERROR; session-aware aggregate. Handle out-of-order, duplicate, corrected past bar. Preserve canonical older snapshots and data-source error logs. New provisional M1 updates overlays only, không mutate last completed candle.
(3) Determine first dirty timestamp per dependency and TF, propagate affected subgraph through L2–L5. Keep warmup state before dirty start for streaming indicators; if input history insufficient for seed or corporate action rewrites history, fall back to full recompute from verified start. Must do full-vs-incremental comparison in tests with tolerance for float only; zone/audit/decision exact.
(4) L2 update EMA/ATR/RSI/other indices from validated closed bars; provisional indicator preview must be marked estimated/not-confirmed. Compare exact status of data freshness, carry flags.
(5) L3 update causal pivot and structure from changed bars, respecting right-bars; L4 run/reuse validate all 16 zone IDs per symbol, calculate SHORT/SWING independently, Exit Protection. Feature lacking verified data => UNVERIFIED with explicit reason.
(6) L5 enforce audit and publish gate. Stage ReportRenderer contract UI-1.0 + immutable evidence and history; after Step08 report+history commit succeeds mark COMPLETE then publish Full Analysis; if any mandatory gate fails return ERROR/INCOMPLETE status, no confirmed trade advice.
(7) Write per-run manifest with source errors and provenance: run_id, symbol(s), time, 8 stages each COMPLETE/FAILED/BLOCKED/NOT_STARTED, 16-zone coverage and unresolved counts, both strategies, cache hits, bytes fetched, delta bars, recomputed indicators/buckets, invalidation reasons and output status.
No automatic schedule or broker order execution approved. This describes what happens whenever the user asks for the scan. No background cache update unless separately authorized.


9. BỘ NHỚ & PHỤC HỒI: PERSISTENCE, CONCURRENCY, RETRY


Thiết kế storage engine-neutral: immutable source snapshots (content-addressed), canonical candle partition by symbol/TF/day, indicator checkpoint per confirmed bar, graph dependency manifest, structure/zone checkpoints, report/audit histories. Primary persistent location cần được xác minh/cho phép trong phạm vi riêng Swing Trading 1.8; không tự tái sử dụng các cache CK/FX/MOCHI đang hoạt động. Google Drive hiện dùng cho tài liệu dự án; upload dữ liệu giá/cache cần định dạng, quotas và permission verification trước khi chọn nơi lưu production.
Atomicity: per-symbol snapshot lock/optimistic revision compare; two concurrent scans cannot publish mismatched artifacts. Build new revision in staging, validate source/config/step manifest, commit manifest pointer via compare-and-swap/transaction where backing store supports, then expose as current; failed publish cannot replace good last-known cache or claim 8/8 COMPLETE. Retain rollback evidence, never use rollback cache as if current.
Retry: exponential backoff with budget and provider limits; no endless synchronous loops; idempotency by run_id, source request scope, content digest. On transient outage prefer LAST_KNOWN with STALE label, not a confirmed signal. Do not recompute expensive L3/L4 if upstream content identical and quality status/versions valid. Concurrent symbol batches may share INDEX/SECTOR snapshots with verified same decision clock; no cross-symbol poisoning.


10. TƯƠNG THÍCH CÁC KỸ THUẬT CHỈ BÁO VÀ EARLY DETECTION


Indicators contract per TF: input price basis, exact warmup length, last valid closed bar, last computed checkpoint, params version, floating tolerance, calculation mode FULL|INCREMENTAL|REUSED_VALIDATED, source quality. EMA/RMA/ATR recursive indicator must restore prior computed state before modified bar, then walk forward; rolling indicators require enough historical lookback. No 'counting new RSI' repeatedly for one provisional minute update.
RVOL_TOD requires same slot & exchange/session over sufficient comparable days (P15 proposed 20), careful lunch/ATO/ATC/no trade. VWAP exact requires reliable matched trade value or defined provider's equivalent; average OHLC price weighted by volume is a proxy, must label APPROX if used at all. Industry RS requires sector index benchmark series with controlled constituent definitions, not peers' latest quote as a time series.
M15 baseline + M5 adaptive ARMED belongs to next GĐ3/B4; B3 provides contract only: arm near watch zone with hysteresis and expiry, never skip 16 detectors when M5 disabled; if M5 required for an asserted trigger and absent, mark UNVERIFIED, don't quietly downgrade requirements.
Protective sell with position takes precedence but must account settlement/price limits and executable timestamps. UI v1.0 display sections and audit evidence remain unchanged.
